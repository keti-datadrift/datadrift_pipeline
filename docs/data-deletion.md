# 데이터와 워크스페이스 삭제

## 화면에서 사용

- **이미지 선택 삭제**: 워크스페이스 안에서 `이미지 선택`을 누르고 이미지를 선택한 뒤 `선택 삭제`를 누릅니다. `현재 페이지 전체 선택`은 현재 화면에 표시된 이미지만 선택합니다. 검색, 분할, 페이지, 데이터셋을 바꾸면 선택이 초기화됩니다.
- **전체 데이터 삭제**: `데이터 작업 > 전체 데이터 삭제`를 누릅니다.
- **워크스페이스 삭제**: 워크스페이스 상단의 `워크스페이스 삭제`를 누릅니다. 포함된 이미지 수를 확인하고 워크스페이스 이름을 입력해야 삭제됩니다. 이미지 수는 현재 목록의 이미지 수입니다.
워크스페이스 화면에는 삭제 목록이나 복원 창을 표시하지 않습니다. 운영상 복구가 필요한 경우 아래 기존 복원 API를 사용합니다. 워크스페이스가 삭제되어 있다면 워크스페이스를 먼저 복원합니다.

삭제는 목록에서 제거하고 새 학습·평가·재구성·드리프트·레이블링 작업의 입력으로 사용할 수 없게 하는 작업입니다. 이미지 원본 파일과 모델 가중치를 영구 삭제하지 않습니다. 파일을 공유하는 다른 데이터셋 버전과 기존 작업 결과는 유지됩니다. 삭제 목록에는 자동 만료나 영구 삭제 기능이 없습니다.

이미지를 삭제하면 현재 목록에서 제거합니다. 선택 삭제를 복원하면 해당 이미지만 현재 목록에 추가하고, 삭제 후 수정한 다른 이미지의 레이블은 유지합니다. 같은 이미지가 이미 등록되어 있다면 현재 레이블을 우선합니다. 워크스페이스 전체를 복원해도 하나의 이미지 목록으로 돌아옵니다.

대기 또는 실행 중인 작업에서 사용하는 데이터는 삭제할 수 없습니다. 취소를 요청한 실행 중 작업도 실제 종료되어야 합니다. 드리프트의 기준 데이터셋도 보호합니다. 완료된 작업과 모델은 유지되며, 삭제한 데이터셋을 복원하면 기존 ID로 다시 조회할 수 있습니다.

## API

1. `POST /api/deletions/preview`: `{ "kind": "workspace" | "dataset" | "samples", "id": "대상 ID", "sample_ids": ["이미지 ID"] }`. `sample_ids`는 samples에만 사용합니다.
2. `POST /api/deletions`: 위 요청에 미리보기 응답의 `token`을 추가합니다. 현재 대상과 토큰이 다르거나 작업이 시작되었으면 409로 차단합니다. 이미지 선택 삭제 응답의 `dataset`에 남은 데이터의 새 버전을 반환합니다.
3. `GET /api/deletions`: 삭제 묶음과 삭제 시각, 대상 이름, 개수를 반환합니다.
4. `POST /api/deletions/{batch_id}/restore`: 삭제 묶음 전체를 트랜잭션으로 복원합니다.

SQLite의 `deleted_objects`에 삭제 당시 객체를 그대로 보관하고, `deletion_batches`에 묶음 정보를 저장합니다. 일반 조회와 이미지 제공 인덱스에서는 삭제한 ID가 제거됩니다. 삭제, 복원, 작업 등록, 재구성 저장은 쓰기 잠금 아래에서 대상을 검사해 동시에 실행되더라도 삭제된 데이터를 새로 참조하는 작업이 생기지 않도록 합니다. 삭제된 내부 ID를 덮어쓰지 않습니다. 삭제한 이미지를 다시 업로드하면 현재 목록에 추가하며, 이후 삭제 목록을 복원하더라도 같은 이미지가 중복되지 않습니다.

운영 백업에는 `catalog.sqlite` 전체와 이미지 저장소를 함께 포함해야 합니다. 삭제해도 디스크 공간은 확보되지 않습니다.

## 검증

`PYTHONPATH=. .venv/bin/python -m pytest tests/test_deletions.py -q`로 별도 임시 DB에서 삭제/복원, 실행 작업 차단, 오래된 미리보기 거부, 다른 워크스페이스 보존, 원본 파일 유지, 복원 실패 시 롤백을 확인합니다.

`node tests/deletion-browser.cjs`는 공개 서비스에 `QA 삭제 복원 검증` 워크스페이스를 만들고 실제 업로드·화면 삭제와 API 복원을 수행하고 삭제 목록 버튼이 없는지 확인합니다. 실행 전에 `.runtime/deletion-verification/one.png`, `two.png` 테스트 이미지를 준비합니다. 기존 운영 데이터는 대상으로 삼지 않습니다. 결과 ID는 해당 디렉터리의 `receipt.json`에 기록되며, `PYTHONPATH=. .venv/bin/python tests/cleanup_deletions.py`로 테스트 소유 데이터만 정리합니다.
