## 제출용 ZIP 설정 파일과 경로 정리 — 2026-10-30

- 기본 제출 ZIP에 `package.json`, `package-lock.json`, `tsconfig.json`, Python 의존성 목록·잠금 파일, 속성 사전 JSON과 LICENSE를 포함하도록 변경했습니다. 총 95개 파일이며, 서버별 `deploy/` 설정과 문서·DB·업로드·모델·환경변수 파일은 제외합니다. 서비스 설정을 추가하는 `--profile runnable`은 별도로 유지합니다.
- 개인 계정 경로가 들어 있던 모델 기본 경로 2곳을 정리했습니다. 기본 모델과 교사 모델은 `DATADRIFT_MODELS` 아래에서 찾고, 생략 시 프로젝트의 `models/`를 사용합니다. 운영 서비스에는 기존 모델 위치를 환경변수로 지정하여 정상 모델 8개와 모델 API의 사용 가능 상태를 유지했습니다.
- Python 전체 155개, Ruff 검사·포맷 검사와 패키징 회귀 검사를 통과했습니다. 제출 ZIP과 서비스 설정 포함 ZIP 모두 별도 폴더에서 기존 진입점·속성 사전과 모델 경로 설정을 가져오는 검사를 통과했습니다.
- 제출 ZIP을 별도 폴더에 풀어 `npm ci --offline`, 새 Python 가상환경의 잠금 의존성 설치와 `pip check`, `npm run build`를 통과했습니다. 새 환경에서 API 시작·속성 사전 조회·워크스페이스 생성·이미지 업로드·워커 시작을 확인했습니다. 모델 파일이나 GPU 의존성은 새로 설치하지 않았습니다.
- 최종 ZIP 95개 파일의 이름과 내용을 검사했습니다. 개인 계정명·이메일·개인 디렉터리·비루프백 IP·인증값·전화번호·주민번호 패턴은 발견되지 않았습니다. 별도 실행 안내서도 개인 경로와 운영 서버 주소를 설치용 예시로 바꿨습니다. 이 검사는 허용 파일 목록과 문자열 패턴 점검 범위의 결과입니다.
- 운영 서버의 기존 서비스 4개는 계속 실행 중이며 health 응답, 정상 모델 8개와 모델 API 사용 가능 상태를 확인했습니다. 실행 진입점과 포트는 같습니다. 제출 ZIP에는 서비스 파일이 없으므로 상시 운영 서비스는 설치 담당자가 구성합니다.

## 백엔드 패키지 정리 — 2026-10-30

- 루트의 내부 Python 모듈 20개를 `data/`, `schemas/`, `models/`, `jobs/`, `drift/`로 이동했습니다. 기존 `routes/`와 API·워커·학습·레이블링·모델 실행 관리자·카탈로그 전환 진입점은 유지합니다. 속성 사전 JSON은 `schemas/`에 함께 배치했습니다.
- 관련 import, 내부 드리프트 하위 프로세스 경로, 검증 스크립트와 ZIP의 필수 파일 목록을 새 경로로 변경했습니다. 대화 맥락을 설명하던 주석과 중복 표현을 다듬었으며 레이블 출처, 모델 프롬프트, 속성 사전 내용과 LICENSE는 보존했습니다. 프런트엔드 변경은 주석에 한정됩니다.
- 기존 Python 테스트 150개와 실행 구성 ZIP을 별도 폴더에 풀어 기존 진입점과 속성 사전을 가져오는 회귀 테스트 1개를 통과했습니다. Ruff 검사·포맷 검사, TypeScript 타입 검사, Prettier 검사와 `git diff --check`도 통과했습니다. 기존 Starlette 테스트 클라이언트 경고 1개는 남아 있습니다.
- 변경 전후 백엔드 38개 모듈의 구문 트리를 비교했습니다. import·설명 문자열, 속성 사전 로딩 위치와 내부 드리프트 실행 경로를 제외한 로직이 같음을 확인했습니다. 설치·운영 안내서의 명령 블록과 systemd 서비스 파일은 동일합니다.
- 운영 작업 대기열이 비어 있음을 확인한 뒤 기존 API·워커·vLLM 실행 관리자를 다시 시작했습니다. 웹을 포함한 기존 서비스 4개가 active이며 health·워크스페이스·모델·작업·속성 사전·모델 API 조회가 HTTP 200으로 응답했습니다. 실제 서버의 OpenAPI도 변경 전 35개 경로 및 스키마와 동일합니다.
- 임시 이미지와 별도 임시 폴더로 새 내부 CPU 드리프트 명령 `python -m backend.jobs.drift`의 결과·진행 파일 생성을 확인했습니다. 운영 데이터에 작업을 추가하거나 새 GPU 학습·평가를 실행하지 않았습니다.
- 핵심 소스 ZIP은 87개 파일, 실행 구성 ZIP은 101개 파일입니다. 실행 명령과 포트는 기존과 같으며 내부 모듈을 직접 가져오는 별도 코드는 [소스 구조](source-structure.md)의 새 패키지 경로를 사용합니다.

## 소스 구조 정리와 제출 ZIP — 2026-10-29

- FastAPI 진입점의 HTTP 처리를 `backend/routes/`로, 요청 형식과 공통 검증을 별도 모듈로 분리했습니다. 변경 전·후 및 실제 반영 서버의 OpenAPI를 비교해 35개 경로와 요청·응답 스키마가 동일함을 확인했습니다.
- 워커의 하위 프로세스 실행·진행 수집·취소·로그 처리를 `job_execution.py`로 통합하고 모델 입력 구성과 결과 반영을 분리했습니다. 기존 모델 선택, 입력 스냅샷, GPU 지정, 원자적 결과 저장과 취소 동작을 유지합니다.
- 대시보드의 워크스페이스·모델·평가·학습·드리프트·재구성 화면, 모델 API의 목록·결과·이력, 드리프트 판정 요약을 별도 구성 요소로 분리했습니다. 조회 훅, 요청 처리, 도메인 타입과 숫자·상태 표시 함수를 공통화했습니다.
- Python Ruff 검사·포맷 검사, Python 전체 **150건**, TypeScript 타입·미사용 변수 검사, Prettier 검사와 프로덕션 빌드를 통과했습니다. 기존 Starlette 테스트 클라이언트의 사용 중단 예정 경고 1개는 남아 있습니다.

- 실행 구성 ZIP을 별도 폴더에 풀고 `npm ci --offline`, 새 Python 3.12 가상환경의 잠금 의존성 설치와 `pip check`, 별도 API 주소를 지정한 웹 빌드를 완료했습니다. 별도 빈 DB·모델 없음 환경에서 웹·API·워커 기동, 브라우저 워크스페이스 생성·이미지 업로드·이미지 표시와 주요 페이지 접속을 확인한 뒤 임시 검증 프로세스만 종료했습니다. 모델 가중치·GPU 패키지는 ZIP에 포함하거나 새로 설치하지 않았습니다.
