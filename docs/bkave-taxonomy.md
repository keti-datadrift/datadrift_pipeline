사용자가 제공한 `비케이브_Taxonomy_공유.xlsx`의 세 시트를 파싱했습니다.
원문 SHA256과 행 번호는 `backend/bkave_taxonomy.json`에 보존합니다.
기준 ID: `bkave-106baf22f720`. 이전 14속성 기준은 `visual-v1`입니다.

| 구분 | 적용 |
| --- | --- |
| 상품 카테고리 | 64개 원문 코드·대/중/소분류·성별 표기를 사전에 보존. 상품 분류 모델을 새로 학습하지 않음 |
| 색상 | 212개 코드를 원문 이름·색상군과 함께 표시. 같은 이름의 다른 코드를 합치지 않음 |
| 상의 | 핏·기장·소매 길이·넥라인·무늬·디자인 디테일 |
| 아우터 | 핏·기장·넥라인·무늬·디자인 디테일 |

| ACC | 무늬·디자인 디테일 |
| 공통 | 원단 유형·생산처, 별도 색상 시트의 색상 코드 |

모델에는 기존 데이터의 상품 카테고리를 문맥으로 제공하고, 해당 카테고리의 허용값만 사용합니다.
출력 키는 공통 9개이며 카테고리에 없는 속성은 시스템 값 `not_applicable`입니다.
미확인은 `unknown`이며 두 시스템 값은 엑셀의 신규 정의값으로 취급하지 않습니다.

## 기존 데이터 변환

원본 무신사 1,000개와 GS SHOP 651개의 이미지·분할을 유지한 새 버전을 만들었습니다.
기존 균형 200개 재구성도 별도로 변환했습니다. 원본 데이터와 이전 모델·실행 결과는 수정하지 않았습니다.

- 상의/아우터의 `레귤러 → 레귤러핏`, 상의 `반팔 → 반소매`, `라운드 → 라운드넥`처럼 명확한 동의어만 변환합니다.
- 하의의 레귤러·슬림 등은 엑셀 원문 그대로 사용합니다. 풀렝스/발목 같은 기존 기장을 임의로 롱/9부로 단정하지 않습니다.
- 예전 무지 레이블은 작은 로고를 무시했으므로 그래픽 위치가 있는 경우 새 무늬 정답으로 사용하지 않습니다.
- 데님외관→데님, 니트조직/케이블니트→니트, 플리스→플리스만 원단 유형으로 대응합니다. 평활→우븐처럼 근거 없는 추측은 하지 않습니다.
- 기존 디테일은 새 어휘 전체를 검토한 것이 아니므로 대응되는 양성값은 검토용으로 표시하되 필드 전체는 학습/평가에서 제외합니다.
- 생산처·세부 색상 코드는 원본 정답이 없어서 미확인으로 두고 제외합니다. 이미지에서 생산 국가를 추측하지 않습니다.
- 변환은 사람 검토가 아닙니다. AI 레이블 출처·이전 값·변환 이력을 보존하고 사람 검토 완료는 false입니다.

이 표는 전체 원본의 필드별 유효 수이며 학습 스텝 수나 모델 정확도가 아닙니다.
새로운 정의값 전체에 대한 정답 데이터가 확보된 것은 아닙니다. 해당 항목은 수동 검토·보완이 필요합니다.

## 호환성

데이터 재구성·드리프트는 동일 기준끼리만 허용합니다. LoRA 모델은 학습한 기준과 같은 데이터셋에만
연결하며 기본 모델은 두 기준을 지원합니다. 레이블 편집은 데이터셋의 기준 ID와 상품 카테고리로
허용값을 불러옵니다. 기존 버전 선택 시 기존 편집 화면도 유지됩니다.

학습 시 새 모델에 기준 ID·원문 사전 스냅샷·프롬프트를 저장합니다. 과거 평가 결과를 새 기준의 결과로
재해석하거나 덮어쓰지 않습니다. `scripts/run_bkave_experiment.py`의 실행 결과와 job ID는 별도 검증 문서에 기록합니다.
