# 복합 드리프트 탐지

`/ko/monitoring/drift`에서 기준·비교 데이터와 속성 변화 기준(JS)을 선택합니다. 새 실행은 `composite-v1`로 저장하며 속성 구성, 같은 카테고리 내 속성, 카테고리 비율, 이미지 특징을 함께 비교합니다. 이전 결과는 당시의 JS 판정을 보존하고 화면에서 이전 방식임을 표시합니다.

## 화면에서 결과 확인

분석 결과가 있으면 화면 맨 위에 `드리프트 감지됨`, `드리프트 감지되지 않음`, `드리프트 판정 보류` 중 하나를 표시합니다. 작업 실행이 완료됐다는 상태와 드리프트 판정을 구분하고, 해당 결과의 비교 대상·개수·분석 시각을 함께 보여줍니다. 항목별 표에는 감지 여부와 달라진 속성 등 사람이 읽을 수 있는 이유를 표시합니다. 일부 항목을 판정하지 못했어도 다른 항목에서 변화가 검출되면 감지 결과와 분석 한계를 함께 표시합니다.

통계값과 판정 기준, 속성별 상세 분포, 새 비교 설정, 이전 분석 이력은 기본적으로 접혀 있습니다. `새 비교 실행`에서 기준·비교 데이터를 고르고 실행하며, JS 기준은 `분석 옵션`에서 조절합니다. 이전 JS 결과도 전체 판정을 보여주되 이전 기준의 결과임을 명시합니다.

## 판정

| 항목 | 변화량 | 통계 검정 | 감지 조건 |
| --- | --- | --- | --- |
| 속성 구성 | 속성값 분포의 JS | 합동 빈도 기반 순열 검정 | JS가 설정값 이상이고 보정 p ≤ 0.05 |
| 카테고리 내 속성 | 공통 카테고리별 JS의 가중 평균 | 카테고리별 순열 검정 | 위와 동일 |
| 카테고리 비율 | 상품 카테고리 분포의 JS | 합동 빈도 기반 순열 검정 | 위와 동일 |
| 이미지 특징 | 고정 이미지 임베딩의 MMD² | RBF 커널의 집단 라벨 순열 검정 | 보정 p ≤ 0.05 |

속성·카테고리·이미지에서 실시한 **모든 검정에 한 번의 Holm 보정**을 적용합니다. 기본 유의수준은 0.05, 순열 수는 999, 기본 seed는 42입니다. 한 항목 이상 기준을 충족하면 `detected=true`이며 어떤 항목인지 별도로 표시합니다. 이미지 특징의 MMD 값에 속성용 JS 임계값을 적용하거나 서로 다른 척도를 임의로 더하지 않습니다.

속성마다 양쪽 유효 레이블이 최소 20개 필요하고, 카테고리 내 검정은 해당 카테고리에서 양쪽 최소 20개가 있어야 포함합니다. 미레이블·unknown·not_applicable·평가 제외 속성은 속성 검정에서 제외합니다. 카테고리 구성은 알려진 상품 카테고리만 사용합니다. 레이블이 없는 동일 스키마 데이터도 접수할 수 있지만 속성 근거가 부족함을 표시합니다.

같은 이미지의 반복을 표본 수로 세지 않습니다. 각 데이터 내부 중복을 제거하고, 두 데이터에 공통인 이미지는 독립 표본 검정에서 제외합니다. 이미지·레이블이 양쪽 모두 완전히 동일하면 검정 없이 동일 입력임을 표시합니다. 공유 이미지를 제외한 표본이 부족하거나 일부 속성 레이블이 부족하면 `complete=false`이고, 감지 근거도 없으면 `decision=insufficient`로 종합 판정을 보류합니다. `not_detected`는 유효한 속성·이미지 비교 범위에서 감지되지 않았다는 뜻입니다. 공유 이미지만 있고 그 레이블이 달라진 경우에는 독립 표본 드리프트로 판정하지 않고 판정 한계를 표시합니다.

입력 개수 `reference_count`, `current_count`와 실제 검정 입력 `analysis_reference_count`, `analysis_current_count`를 구분합니다. 이미지 분석은 각 도메인에서 최대 256장을 SHA 정렬·seed 기반으로 선택하며 속성 통계는 전체 유효 입력을 사용합니다. 선택 이미지의 순서 해시도 결과에 남깁니다.

RGB 히스토그램 JS는 비교용 참고값으로 보존하지만 새 종합 경고의 근거로 쓰지 않습니다. 배경색만 비슷해도 상품 형태·무늬·촬영 구도가 다를 수 있어 이미지 특징 검정을 별도로 수행합니다. 임베딩 검정의 민감도는 고정 인코더가 표현한 특징에 한정됩니다. 이 분석은 데이터 분포 비교이며 모델의 실제 성능 저하를 확정하지 않습니다. 현재 운영 데이터의 AI 레이블은 사람 검증 정답과 구분해서 해석해야 합니다.

## 이미지 특징과 캐시

- 고정 모델: torchvision ResNet18, ImageNet-1K V1 사전학습 가중치, 학습·LoRA 변경 없음.
- 가중치 SHA256: `f37072fd47e89c5e827621c5baffa7500819f7896bbacec160b1a16c560e07ec`.
- 입력: EXIF 회전 보정·RGB, 가중치의 공식 전처리(256 리사이즈·224 중앙 크롭·ImageNet 정규화).
- 출력: 분류기를 제거한 512차원 특징, L2 정규화.
- 이미지 검정: 양쪽을 합쳐 정한 거리 중앙값을 기준으로 0.5·1·2 배율의 RBF 커널 평균을 사용하고, 커널을 고정한 채 집단 라벨을 순열화합니다. 편향 MMD² 추정량의 순열 검정이며 결과를 정확도나 손실로 해석하지 않습니다.
- 실행: 기존 GPU Python 환경의 별도 **CPU 전용 프로세스**, 최대 8개 CPU 스레드, 16장 배치. `CUDA_VISIBLE_DEVICES`를 비워 API GPU 메모리 설정에 영향을 주지 않습니다.

캐시는 `.runtime/image-features/{인코더 버전 해시}/{이미지 SHA256}.npy`에 저장합니다. 인코더 버전에는 가중치 전체 해시·전처리 버전·torch/torchvision 버전을 포함합니다. 캐시를 읽기 전 원본 이미지의 현재 바이트 해시를 확인하고 저장된 SHA와 다르면 실패합니다. 캐시는 원자적으로 교체하고 모양·유효값이 잘못된 캐시는 재계산합니다. 레이블만 바뀐 데이터는 이미지 특징을 다시 계산하지 않습니다. 캐시는 파생 데이터이므로 삭제 시 다음 분석에서 재생성됩니다.

운영 호스트에는 `~/.cache/torch/hub/checkpoints/resnet18-f37072fd.pth`가 준비돼 있습니다. 새 호스트에서는 [torchvision 공식 가중치](https://download.pytorch.org/models/resnet18-f37072fd.pth)를 해당 경로에 내려받고 위 전체 SHA256을 확인하세요. 실행 중 자동 다운로드하거나 임의 가중치로 대체하지 않습니다. 가중치나 추출 환경 오류가 생기면 작업을 실패로 표시하며 색상 히스토그램만으로 성공 처리하지 않습니다.

## 실행과 호환성

기존 `POST /api/jobs`의 `kind=drift`, `dataset_id`, `reference_id`, `threshold`, `seed`를 사용합니다. 기존 비동기 작업 등록·조회·취소와 단일 워커 큐를 유지합니다. 새 작업에는 기준 데이터 fingerprint도 고정하며 실행 전 입력 스냅샷을 확인합니다. CPU 하위 프로세스를 취소하면 프로세스 그룹을 종료하고 결과를 게시하지 않습니다.

진행 단계는 데이터 준비, 속성 검정, 이미지 모델 준비, 이미지 특징 추출, 이미지 검정, 결과 정리로 표시합니다. 입력·진행·결과·실행 로그는 `.runtime/jobs/{job_id}/drift-input.json`, `progress.json`, `result.json`, `process.log`에 보관합니다. 서비스·로그·재시작 방법은 [운영 문서](operations.md)를 따릅니다.

`fields`, `detected`, 입력 개수, `image_histogram_js`를 유지하고 다음 결과 필드를 추가했습니다.

- `method_version`, `decision`, `complete`, `signals`: 방식·종합 판정·분석 범위·항목별 결과.
- `image_embeddings`, `category_mix`, `correction`, `quality`: 검정값·보정 p·모델/캐시 출처·중복/공유 입력 정보.
- 속성의 `status`, `adjusted_p_value`, `category_adjusted_p_value`, `category_detected`: 표본 부족과 종합 보정 결과. 과거의 속성군 BH `q_value`는 참고 통계로 보존하고 새 판정에는 전체 Holm 보정 p를 사용합니다.

## 검증

Python 테스트는 같은 분포, 속성만 변화, 이미지만 변화, 카테고리 구성비와 카테고리 내부 변화 구분, 표본 부족, 동일 입력, 공유·중복 제거, seed 재현, Holm 보정, 미레이블 입력, CPU 실행·기준 스냅샷 확인·취소를 검증합니다.

실제 GS SHOP 651장·무신사 1,000장 비교에서 속성 7개 중 2개, 같은 카테고리 내 속성 7개 중 4개와 이미지 특징의 변화가 감지됐습니다. 이미지 MMD²는 0.06581, 전체 16개 검정의 Holm 보정 p는 0.016이었습니다. 카테고리 비율의 JS는 설정 임계값 미만이어서 경고하지 않았습니다. 서비스 작업 `8101422c73834991b3898c80229db4c1`은 CPU에서 특징 512개를 재사용해 9.61초에 완료했습니다. 별도 합성 검증에서는 색상 JS=0·동일 속성에서도 이미지 MMD 검정만 변화를 감지했습니다. 이는 검증 사례이며 모든 종류의 변화나 모델 성능 저하를 검출한다는 보장은 아닙니다.

브라우저 검사는 `node tests/drift-composite.cjs`로 실행합니다. 운영 데이터에 새 작업을 등록하지 않고, 준비된 `.runtime/drift-composite/result.json`을 모의 응답으로 사용해 네 항목·보정 p·표본 부족·진행 단계·이전 결과와 PC/모바일 배치를 검증합니다.

방법 근거: [MMD 원논문](https://www.jmlr.org/papers/v13/gretton12a.html), [torchvision ResNet18·전처리](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html).
